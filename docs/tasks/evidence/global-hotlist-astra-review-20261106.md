## 总榜方案与第二轮修复

- 对外仅一个全站帖子榜；内部七片保存同一公式的完整比较键，按 revision／generation／policy／next_change 复用。单片变更不要求全站重算。均匀七片且仅一片变动、无到期边界时，重算候选约为全量1/7；这是工作量，非延迟承诺。
- PostgreSQL 每块最多64个候选；Redis 单一全站排序集合保存各片首64的并集，最多448项。比较顺序为正分标记、十二位对数分、发布时间、全局发表序号；Go用 `big.Rat` 避免浮点损失。
- 常态先投影精确的全站前64，能产生20条有效记录便可返回。否则检查完整并集的各片覆盖；不足以证明完整性时，逐块找到各允许分片前20条有效记录，再精确合并。
- 修复 P1：A片前64下架63条，B片凑满20会掩盖A深处高分内容。不能只检查全局条数；已加入 A85高分＋B20低分的真实 HTTPS 回归。
- 修复 P2：`has_table_privilege` 的逗号列表表示“任意权限”，已改为逐项检查并 `bool_and`。语义依据见 [PG16 权限查询函数](https://www.postgresql.org/docs/16/functions-info.html#FUNCTIONS-INFO-ACCESS-TABLE)。
- 增强完整性：每片每块的实际长度必须匹配元数据，另一片有数据不能掩盖缺块；数据库限制数组等长、无 NULL、块长度。完整版本提交后才发布 Redis 指针。
- 屏蔽在最终事务再读；预取期间发生变化会重试。缓存和私有候选不授予任何内容权限。未来快照测试同时 Stage 候选，覆盖最终可信时间拒绝后的 SQL 回退。
- v2缓存使用独立前缀。已用受 ACL 限制的临时用户验证 v1-only 拒绝、增加v2后 Stage／Publish／Snapshot／Candidates 成功。

## 算法与体验边界

沿用近168h帖子、赞1／藏2／独立讨论者3、48h半衰期。它衡量累计有效互动与帖子年龄，不是最近互动增速。所有正分帖排在零分新帖之前，存在冷启动弱的问题；同一非作者账号最多可贡献6分，多账号仍可能刷榜，对数变换本身不是抗刷。

正常刷新为0–5min加计算时间，下拉与详情返回重读快照；当前页没有按快照年龄自动刷新。新帖探索位、账号可信度、单作者曝光限制和恢复前台刷新策略没有在本次未经确认改动。
